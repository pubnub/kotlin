DataSyncNamespace

object DataSyncNamespace

DataSync PAM v3 namespaces and helpers.

ENTITIES, RELATIONSHIPS and MEMBERSHIPS appear literally as keys under the token's res/pat blocks, as siblings of chan/grp/uuid. USERS_PROJECTION and CHANNELS_PROJECTION do not: see their docs.

CHANNELS_PROJECTION
Link copied to clipboard
const val CHANNELS_PROJECTION: String

Namespace of DataSyncGrant.channel / DataSyncGrant.channelPattern. Like USERS_PROJECTION it is not a permission bucket: the permission bits go into the plain channels bucket (shared with pub/sub and App Context v2), and this string appears only as the prefix of the pn-projections composite key (datasync:channels:<id>).

USERS_PROJECTION
Link copied to clipboard
const val USERS_PROJECTION: String

Namespace of DataSyncGrant.user / DataSyncGrant.userPattern. It is not a permission bucket: the permission bits of those grants go into the plain users bucket, and this string appears only as the prefix of the pn-projections composite key (datasync:users:<id>) (server team, 2026-08-07). Note this contradicts the ADR examples, which key every projection under datasync:entities:<id>.
